## 3. Final Invitation Flow
1. **ADMIN:** Submits the new client form. `inviteUserByEmail()` is triggered.
2. **EMAIL:** Supabase sends an email containing the `token_hash`.
3. **CALLBACK:** The user clicks the link. Next.js catches `/auth/callback?token_hash=...`.
4. **VERIFY:** The server exchanges the token for a session using `verifyOtp()`.
5. **SESSION:** The `@supabase/ssr` client writes `Set-Cookie` headers into the redirect response.
6. **ACCEPT:** The browser redirects to `/invite/accept`. Next.js verifies the session and displays the user's email.
7. **SETUP:** The user sets a password. `updateUser()` is called, the session is refreshed, and the user lands on `/dashboard`.

## 6. Session/Cookie Handling
When `verifyOtp()` succeeds, `@supabase/ssr` automatically sets the session cookies via the Next.js `cookies().set()` API. Because this is a Server Route Handler returning a `NextResponse.redirect`, Next.js successfully injects the `Set-Cookie` headers into the response. The browser stores these HTTP-only cookies before following the redirect to `/invite/accept`.

## 7. Invite Accept Handling
`app/invite/accept/page.tsx` uses a client-side session guard to ensure the user is authenticated *before* allowing password setup. It successfully updates the password using `updateUser()`, forces a `refreshSession()` to ensure all claims are populated, and routes to `/dashboard`.

## 8. Session Confusion Handling
If an existing user (e.g., User A) opens User B's invitation link, Supabase's `verifyOtp()` *replaces* the active session in the cookies with User B's session. To prevent the human user from mistakenly setting a password without realizing they are now operating as User B, `app/invite/accept/page.tsx` prominently displays the active session's email: *"Welcome! Please create a secure password to activate your account for **marketivity.tryon@gmail.com**"*.
